# Руководство по созданию сцен для игры "Twilights"

## Обзор

Игра "Twilights" представляет собой RPG с механикой "3 в ряд", где игрок управляет персонажами в
различных сценах - от социальных взаимодействий до боевых столкновений. Сцены определяются
JSON-файлами, которые загружаются из Firebase и парсятся в игровые объекты.

> **⚠️ Важно:** JSON стандарт не поддерживает комментарии. Все примеры в этом руководстве содержат
> только валидный JSON без комментариев. Описания полей вынесены в отдельные блоки под примерами.

## Структура JSON-файла сцены

### Основные компоненты

```json
{
  "hero": {},
  "enemy": {},
  "settings": {},
  "heroRules": {}
}
```

**Описание компонентов:**

- `hero`: Объект героя с его характеристиками и навыками
- `enemy`: Объект противника с его характеристиками и действиями
- `settings`: Настройки игры, включая конфигурацию гемов
- `heroRules`: Правила для героя, определяющие комбо-эффекты

## 1. Объект Hero (Герой)

### Базовые свойства

```json
{
  "name": "Имя героя",
  "hp": 100,
  "maxHp": 100,
  "shield": 0,
  "wounds": 0,
  "maxWounds": 3,
  "statuses": [],
  "touches": 0,
  "hits": 0,
  "blocks": 0,
  "wasHitByPreviousEffect": false,
  "wasTouchedByPreviousEffect": false
}
```

**Описание полей:**

- `name`: Имя героя
- `hp`: Текущее здоровье
- `maxHp`: Максимальное здоровье
- `shield`: Текущие щиты
- `wounds`: Раны (опционально)
- `maxWounds`: Максимальные раны (опционально)
- `statuses`: Массив статусов
- `touches`: Количество касаний в ходу
- `hits`: Количество попаданий в ходу
- `blocks`: Количество блоков в ходу

### Примеры героев

- **Perro** (гоблин-ведущий): социальные взаимодействия, репутация
- **Hombro** (орк): боевые столкновения, физические атаки

## 2. Объект Enemy (Противник)

### Базовые свойства

```json
{
  "name": "Имя противника",
  "hp": 80,
  "maxHp": 80,
  "shield": 0,
  "wounds": 0,
  "maxWounds": 2,
  "statuses": [],
  "info": "Описание противника",
  "preview": "test_enemy",
  "touches": 0,
  "hits": 0,
  "blocks": 0,
  "wasHitByPreviousEffect": false,
  "wasTouchedByPreviousEffect": false
}
```

**Описание полей:**

- `name`: Имя противника
- `hp`: Текущее здоровье
- `maxHp`: Максимальное здоровье
- `shield`: Текущие щиты
- `wounds`: Раны (опционально)
- `maxWounds`: Максимальные раны
- `statuses`: Массив статусов
- `info`: Описание противника
- `preview`: Имя файла превью

### Типы противников

- **Социальные**: "Беседа", "Водомерки", "Общины" - для диалоговых сцен
- **Боевые**: "Гнолл", "Хильден", "Стая барранок" - для боевых сцен

## 3. Система ресурсов (Stocks)

### Типы ресурсов (gemType)

- **1-5**: Основные цвета способностей
- **6**: Репутация/Движение (для социальных сцен)
- **7**: Технические действия
- **8**: Специальные ресурсы

### Структура ресурса

```json
{
  "value": 15,
  "gemType": 1,
  "maxValue": 20
}
```

**Описание полей:**

- `value`: Текущее количество
- `gemType`: Тип ресурса
- `maxValue`: Максимальное количество (опционально)

## 4. Навыки (Perks)

### Структура навыка

```json
{
  "name": "Название навыка",
  "description": "Описание эффекта",
  "effects": [],
  "prices": [],
  "icon": "attack",
  "gif": "attack.gif",
  "charges": 2,
  "coolDown": 1,
  "reloadType": "TURN",
  "probability": 100,
  "place": false,
  "conditionsForDisplay": [],
  "conditionsForEnable": [],
  "category": "attack",
  "hideDescription": false
}
```

**Описание полей:**

- `name`: Название навыка
  > **⚠️ Важно:** Каждый навык должен иметь уникальное имя, даже если навыки находятся в разных
  руках и имеют одинаковые эффекты. Это необходимо для корректной работы системы идентификации
  навыков. Используйте синонимы для навыков с похожей функциональностью (например: "Начать
  действовать", "Приступить к действию", "Начать атаку", "Приступить к атаке").
- `description`: Описание эффекта **для игрока**. Не добавляйте сюда «сырую» техническую информацию
  из JSON (названия полей, точные формулы, внутренние флаги), только понятное человеку описание
  того, что навык делает по смыслу, в художественных или упрощённых терминах.
  - Если `description` **не задан**, клиент может выводить **автоматическое техническое описание**
    на основе `effects` (это полезно, когда игроку важно видеть точные числа и механику).
  - Если `description` **задан**, он **полностью заменяет** автогенерируемый текст: используйте это,
    когда хотите скрыть детали реализации и дать только сюжетное/упрощённое объяснение.
- `effects`: Массив эффектов
- `prices`: Стоимость использования
- `icon`: Иконка навыка
- `gif`: Анимация (опционально)
- `charges`: Количество зарядов (количество использований навыка). Если указано, навык можно
  использовать указанное количество раз, после чего он становится недоступным.
- `coolDown`: Время перезарядки
- `reloadType`: Тип перезарядки
- `probability`: Вероятность срабатывания
- `place`: Пассивный навык
- `conditionsForDisplay`: Условия показа
- `conditionsForEnable`: Условия доступности
- `category`: Категория навыка

**Пример условий видимости:**

```json
"conditionsForDisplay": [
  {
    "parameter": "STATUS",
    "name": "Ладрон: Найден",
    "target": "HERO",
    "symbol": "EMPTY"
  }
]
```

Это условие показывает навык только если у героя НЕТ статуса "Ладрон: Найден".

> **💡 Важно:** `conditionsForDisplay` можно добавлять не только на уровне навыка (`perk`), но и на
> уровне руки (`hand`). Когда условие добавлено на уровне руки, оно применяется ко всей руке - рука
> будет видна только если условие выполнено. Это полезно для скрытия целых групп навыков при
> определенных условиях.

**Пример условия видимости на уровне руки:**

```json
{
  "gemType": 1,
  "name": "Оружие/руки",
  "conditionsForDisplay": [
    {
      "parameter": "STATUS",
      "symbol": "HAVE",
      "target": "HERO",
      "name": "Сделан ход"
    }
  ],
  "perks": [
    ...
  ]
}
```

Эта рука будет видна только если у героя есть статус "Сделан ход".

### Типы перезарядки (reloadType)

- **TURN**: Перезарядка по ходам
- **PERK**: Перезарядка по действиям
- **COMBO**: Перезарядка по комбо (сбрасывается в конце хода)

### Группировка навыков через категории

Навыки с одинаковой категорией (`category`), `coolDown: 1` и `reloadType: "TURN"` образуют группу
взаимно исключающих навыков. Это означает, что за один ход может быть использован только один навык
из этой категории. После использования любого навыка категории, все навыки этой категории становятся
недоступными до следующего хода.

**Пример использования:**

```json
{
  "category": "Восстановление",
  "coolDown": 1,
  "reloadType": "TURN",
  "name": "Восстановить контратаку",
  "effects": [
    ...
  ]
}
```

Этот механизм полезен для создания альтернативных вариантов действий, где игрок или противник должен
выбрать только один из доступных вариантов.

### Заряды (charges)

Заряды определяют, сколько раз навык может быть использован. Это полезно для навыков, которые должны
иметь ограниченное количество использований.

**Структура:**

```json
{
  "name": "Метание сюрикенов",
  "charges": 1,
  "effects": [
    ...
  ]
}
```

**Как это работает:**

- Навык с `charges: 1` можно использовать 1 раз, после чего он становится недоступным
- Если `charges` не указан, навык можно использовать неограниченное количество раз (при выполнении
  остальных условий)
- `coolDown` и `reloadType` не влияют на перезарядку зарядов - они работают независимо

**Примеры использования:**

1. Навык с 1 зарядом (одноразовое использование):

```json
{
  "name": "Метание сюрикенов",
  "charges": 1,
  "effects": [
    ...
  ]
}
```

2. Навык с 2 зарядами (можно использовать дважды):

```json
{
  "name": "Мощный удар",
  "charges": 2,
  "effects": [
    ...
  ]
}
```

> **⚠️ Важно:**
> - Заряды работают независимо от категорий и перезарядки (`coolDown`, `reloadType`)
> - После использования всех зарядов навык становится недоступным

## 5. Эффекты (Effects)

### Типы эффектов (command)

- **ATTACK**: Нанесение урона
- **DEFEND**: Добавление щитов
- **HEAL**: Восстановление здоровья
- **EDIT_STATUS**: Изменение статусов
- **EDIT_STOCK**: Изменение ресурсов (очков)
- **INFO**: Информационное сообщение
- **FINISH**: Завершение сцены

### Типы атак (type для ATTACK)

При использовании эффекта `ATTACK` можно указать тип атаки:

- **По умолчанию (без type)**: Обычная атака по здоровью, может быть заблокирована щитами
- **SP**: Атака по щитам - наносит урон только щитам, игнорирует здоровье
- **HP**: Неблокируемая атака - наносит урон напрямую по здоровью, игнорирует щиты

**Примеры:**

```json
{
  "command": "ATTACK",
  "target": "ENEMY",
  "type": "SP",
  "value": 6,
  "func": {
    "dice": 6
  }
}
```

Эта атака наносит урон только по щитам: 6 + случайное значение от 1 до 6.

```json
{
  "command": "ATTACK",
  "target": "ENEMY",
  "type": "HP",
  "value": 13
}
```

Эта атака наносит 13 урона напрямую по здоровью, игнорируя щиты.

### Типы изменения статусов (EDIT_STATUS)

При использовании эффекта `EDIT_STATUS` можно указать тип изменения:

- **SET**: Установить статус (заменяет существующий)
- **CHANGE**: Изменить статус (увеличивает/уменьшает значение)
- **TIMES**: Изменить количество применений статуса

**Примеры:**

- `"type": "SET"` - устанавливает статус с указанным значением
- `"type": "CHANGE"` - добавляет к существующему значению (позволяет накапливать эффекты)
- `"type": "TIMES"` - изменяет количество применений статуса

> **⚠️ Важно:** Для эффекта `EDIT_STATUS` **обязательно** должно быть поле `value` на уровне
> эффекта (не только внутри объекта `status`). Это значение определяет, какое изменение будет
> применено к статусу. Если значение отсутствует на уровне эффекта, его нужно скопировать
> из `status.value`.

**Пример статуса CHANGE_STOCK:**

```json
{
  "name": "Голос: Резонанс",
  "type": "CHANGE_STOCK",
  "value": 1,
  "duration": -1,
  "gemTypes": [5]
}
```

Этот статус увеличивает получение очков 5-го типа (голос) на 1 при совмещении гемов.

**Пример статуса CHANGE_TURN_KEEP_STRATEGY:**

```json
{
  "name": "Голос: Эхо",
  "type": "CHANGE_TURN_KEEP_STRATEGY",
  "value": 1,
  "duration": -1,
  "gemTypes": [5],
  "times": 4
}
```

Этот статус улучшает сохранение стратегии между ходами для 5-го типа ресурсов, может быть применен 4
раза.

### Изменение ресурсов (EDIT_STOCK)

Эффект `EDIT_STOCK` используется для изменения количества очков (ресурсов) у цели.

**Структура:**

```json
{
  "command": "EDIT_STOCK",
  "target": "HERO",
  "type": "CHANGE",
  "value": -10,
  "gemTypes": [
    3
  ],
  "successType": "TOUCH"
}
```

**Описание полей:**

- `command`: Должно быть `"EDIT_STOCK"`
- `target`: Цель (HERO, ENEMY, SELF, FOE, ALL)
- `type`: Тип изменения
  - **CHANGE**: Изменить количество очков (добавить/отнять указанное значение)
  - **SET**: Установить точное количество очков
- `value`: Значение изменения (может быть отрицательным для уменьшения)
- `gemTypes`: Массив типов ресурсов, к которым применяется эффект (обязательно, если нужно изменить
  конкретные типы)
- `successType`: Условие срабатывания (опционально)
  - **TOUCH**: Срабатывает при касании
  - **HIT**: Срабатывает при попадании
  - **FAIL**: Срабатывает при неудаче
  - **SUCCESS**: Срабатывает при успехе

**Примеры:**

1. Отнять 10 очков движения (тип 3) у героя при касании:

```json
{
  "command": "EDIT_STOCK",
  "target": "HERO",
  "type": "CHANGE",
  "value": -10,
  "gemTypes": [
    3
  ],
  "successType": "TOUCH"
}
```

2. Добавить 5 очков типа 1 и 2:

```json
{
  "command": "EDIT_STOCK",
  "target": "HERO",
  "type": "CHANGE",
  "value": 5,
  "gemTypes": [
    1,
    2
  ]
}
```

### Структура эффекта

```json
{
  "command": "ATTACK",
  "target": "ENEMY",
  "value": 15,
  "probability": -30,
  "pFunc": {
    "segments": [
      {
        "parameter": "STOCK",
        "gemType": 5,
        "source": "HERO",
        "mul": 1.0
      }
    ]
  },
  "func": {
    "dice": 4,
    "segments": [
      {
        "parameter": "STOCK",
        "gemType": 1,
        "source": "HERO",
        "mul": 2.0
      }
    ]
  },
  "repeats": 2,
  "rFunc": {
    "dice": 2
  },
  "conditions": [],
  "additionalEffects": []
}
```

**Описание полей:**

- `command`: Тип эффекта (ATTACK, DEFEND, HEAL, etc.)
- `target`: Цель (HERO, ENEMY, SELF, FOE, ALL)
- `value`: Базовое значение
- `probability`: Базовая вероятность срабатывания (по умолчанию 100%). Может быть отрицательной -
  тогда вычитается из результата pFunc
- `pFunc`: Функция расчета вероятности
  - `segments`: Параметры для расчета вероятности
    - `parameter`: Параметр (STOCK, HP, STATUS, TIME, etc.)
    - `gemType`: Тип ресурса (для STOCK)
    - `name`: Имя статуса (для STATUS)
    - `source`: Источник (HERO, ENEMY, SELF, FOE)
    - `mul`: Множитель
  - **Логика расчета**: Итоговая вероятность = pFunc + probability
    - Если `probability: -30` и у игрока 50 очков типа 5, то вероятность = 50 - 30 = 20%
    - Если `probability: 70` и у игрока 20 очков типа 5, то вероятность = 20 + 70 = 90%
  - **Множественные сегменты**: Можно использовать несколько сегментов одновременно
    - Каждый сегмент умножает свой параметр на свой множитель
    - Все результаты складываются, затем добавляется/вычитается базовая вероятность
  - **Использование STATUS в pFunc**: Можно использовать значение статуса для расчета вероятности
    ```json
    "pFunc": {
      "segments": [
        {
          "parameter": "STATUS",
          "name": "Скорость",
          "source": "ENEMY",
          "mul": 1
        }
      ]
    }
    ```
    В этом примере вероятность зависит от значения статуса "Скорость" у противника
- `func`: Функция расчета значения
  - `dice`: Случайное значение 1-N (можно использовать без segments для простого случайного
    значения)
  - `segments`: Параметры для расчета (опционально)
  - **Простое случайное значение**: Если нужен только случайный бросок без дополнительных параметров
    ```json
    "func": {
      "dice": 6
    }
    ```
    Это даст случайное значение от 1 до 6, которое добавится к базовому `value`
- `repeats`: Количество повторений
- `rFunc`: Функция для повторов
- `conditions`: Условия срабатывания
- `additionalEffects`: Дополнительные эффекты

### Вероятность срабатывания

Вероятность может быть указана на двух уровнях:

**1. Вероятность на уровне навыка (`perk`):**

```json
{
  "name": "Навык",
  "probability": 50,
  "effects": [
    ...
  ]
}
```

> **⚠️ Важно:** Вероятность на уровне навыка имеет смысл только для навыков противника, так как
> противник применяет их автоматически сверху вниз. Для навыков героя вероятность на уровне навыка не
> используется, так как игрок сам выбирает навык.

**2. Вероятность на уровне эффекта (`effect`):**

```json
{
  "command": "INFO",
  "probability": 50,
  "message": "Сообщение",
  "pFunc": {
    "segments": [
      {
        "parameter": "STOCK",
        "gemType": 1,
        "source": "HERO",
        "mul": 1
      }
    ]
  }
}
```

Вероятность на уровне эффекта определяет, сработает ли конкретный эффект. Это основной способ
управления вероятностью для навыков героя.

**Функция вероятности (`pFunc`):**

`pFunc` позволяет динамически рассчитывать вероятность на основе параметров игры. Значение `pFunc`
добавляется к базовой вероятности (`probability`).

**Пример расчета:**

- Базовая вероятность: `probability: 50`
- У героя 30 очков типа 1
- `pFunc` с `mul: 1` дает: 30 × 1 = 30
- **Итоговая вероятность**: 50 + 30 = 80%

### Дополнительные эффекты (additionalEffects)

Дополнительные эффекты срабатывают в зависимости от результата основного эффекта. Для управления
этим используется поле `successType`:

**Типы успеха (`successType`):**

- **HIT**: Дополнительный эффект срабатывает при успешном попадании (для атак)
- **TOUCH**: Дополнительный эффект срабатывает при касании (для атак)
- **FAIL**: Дополнительный эффект срабатывает при неудаче основного эффекта
- **SUCCESS**: Дополнительный эффект срабатывает при успехе основного эффекта

**Пример использования:**

```json
{
  "command": "INFO",
  "probability": 50,
  "message": "Удалось отбить нож",
  "additionalEffects": [
    {
      "command": "HEAL",
      "target": "HERO",
      "value": -8,
      "successType": "FAIL"
    }
  ]
}
```

В этом примере:

- Основной эффект `INFO` срабатывает с вероятностью 50%
- Если основной эффект **не сработал** (`FAIL`), то срабатывает дополнительный эффект `HEAL -8` (
  герой получает 8 урона)
- Если основной эффект сработал, дополнительный эффект не применяется

### Цели эффектов (target)

- **HERO**: Герой
- **ENEMY**: Противник
- **SELF**: На себя (от героя к герою, от врага к врагу)
- **FOE**: На противника (от героя к врагу, от врага к герою)
- **ALL**: На всех

### Источники (source)

- **HERO**: От героя
- **ENEMY**: От противника
- **SELF**: От себя
- **FOE**: От противника

## 6. Статусы (Statuses)

### Типы статусов (type)

- **DAMAGE**: Урон (наносит урон каждый ход)
- **DAMAGE_HP**: Урон по здоровью (наносит урон напрямую по HP, игнорируя щиты)
- **HEAL**: Лечение (восстанавливает здоровье)
- **WEAK**: Слабость (снижение наносимого урона)
- **STRONG**: Сила (увеличение наносимого урона)
- **VULNERABLE**: Уязвимость (увеличение получаемого урона)
- **VUL**: Уязвимость (краткая форма, аналогична VULNERABLE)
- **DODGE**: Уклонение (количество уклонений от ударов)
- **EVASION**: Уклонение (процентное уклонение от атак)
- **ACCURACY**: Точность (изменяет шанс попадания, может быть отрицательной)
- **RESISTANCE**: Сопротивление
- **STUN**: Оглушение (блокирует действия на ход)
- **GENERATE**: Генерация ресурсов (добавляет очки указанных типов при совмещении гемов)
- **DEFEND**: Генерация щитов (добавляет щиты)
- **ARMOR**: Броня (снижает получаемый урон или дает шанс блокировать удар)
- **CHANGE_STOCK**: Изменение получения ресурсов (увеличивает/уменьшает очки от гемов при
  совмещении). **Требует поле `gemTypes`** - массив типов ресурсов, к которым применяется эффект
- **CHANGE_TURN_KEEP_STRATEGY**: Изменение сохранения стратегии между ходами (улучшает сохранение
  очков после хода). Значение указывается **в процентах**. **Требует поле `gemTypes`** - массив
  типов ресурсов, к которым применяется эффект
- **CHANGE_DEFEND**: Изменение защиты (увеличивает/уменьшает эффективность защиты)
- **COUNTERATTACK**: Контратака (автоматическая атака при получении урона)
- **REACTION**: Реакция (эффект, срабатывающий при определенных условиях, может содержать
  reactionEffect)
- **INFO**: Информационный статус (не оказывает прямого эффекта, используется для маркировки
  состояний)

### Структура статуса

```json
{
  "name": "Название статуса",
  "description": "Описание эффекта",
  "value": 5,
  "type": "DAMAGE",
  "probability": 100,
  "duration": 3,
  "gemTypes": [
    1,
    2
  ],
  "times": 2,
  "smartValue": 10,
  "end": false
}
```

**Описание полей:**

- `name`: Название статуса
- `description`: Описание эффекта (опционально)
- `value`: Значение статуса
- `type`: Тип статуса
- `probability`: Вероятность срабатывания (по умолчанию 100)
- `duration`: Длительность в ходах (-1 = бесконечно, по умолчанию 1)
- `gemTypes`: Типы ресурсов (для GENERATE, CHANGE_STOCK, CHANGE_TURN_KEEP_STRATEGY) - массив чисел
- `times`: Количество применений (опционально). Если не задано, статус действует столько раз,
  сколько длится его duration
- `smartValue`: Умное значение (для SMART_DODGE) - уворот сработает только если урон больше этого
  значения
- `reactionEffect`: Эффект для статуса типа REACTION (опционально)
- `end`: **Время применения статуса** (по умолчанию `false`)
  - `false`: Статус применяется и обновляется **перед ходом** персонажа
  - `true`: Статус применяется и обновляется **после хода** персонажа
  - В интерфейсе статусы с `end: true` отображаются с меткой **(E)** в названии

### Время применения статусов

Статусы могут применяться в два разных момента:

1. **Перед ходом** (`end: false`, по умолчанию):
  - Статусы применяются до того, как персонаж начинает действовать
  - Например: генерация щитов перед ходом, урон в начале хода

2. **После хода** (`end: true`):
  - Статусы применяются после того, как персонаж закончил действовать
  - Например: урон в конце хода, лечение после действий
  - В интерфейсе такие статусы помечаются как **(E)** в названии

**Важно:** Длительность (`duration`) статуса уменьшается в момент его применения. То есть статус
с `end: false` уменьшит длительность перед ходом, а статус с `end: true` - после хода.

### Примеры статусов

**Статус урона перед ходом (по умолчанию):**

```json
{
  "name": "Отравление",
  "value": 3,
  "type": "DAMAGE",
  "duration": 3,
  "end": false
}
```

Этот статус нанесет 3 урона перед каждым ходом персонажа в течение 3 ходов.

**Статус урона после хода:**

```json
{
  "name": "Кровотечение",
  "value": 2,
  "type": "DAMAGE",
  "duration": 2,
  "end": true
}
```

Этот статус нанесет 2 урона после каждого хода персонажа в течение 2 ходов. В интерфейсе будет
отображаться как "Кровотечение (E): 2".

**Статус лечения после хода:**

```json
{
  "name": "Регенерация",
  "value": 5,
  "type": "HEAL",
  "duration": 4,
  "end": true
}
```

Этот статус восстановит 5 здоровья после каждого хода персонажа в течение 4 ходов.

## 7. Условия (Conditions)

### Параметры (parameter)

- **HP**: Здоровье
- **HP_P**: Здоровье в процентах
- **STATUS**: Наличие статуса
- **TURN**: Номер хода
- **TOUCHES**: Количество касаний
- **HITS**: Количество попаданий
- **STOCK**: Количество ресурсов
- **TIME**: Время
- **TOUCHED**: Был задет предыдущим эффектом
- **HIT**: Был поврежден предыдущим эффектом

### Символы сравнения (symbol)

- **MORE**: Больше
- **LESS**: Меньше
- **EQUALS**: Равно
- **HAVE**: Имеет
- **EXIST**: Существует
- **EMPTY**: Пусто (отсутствует)
- **NOT**: Не

**Примеры использования:**

- `"symbol": "EMPTY"` - проверяет отсутствие статуса (показывает навык, если статуса нет)
- `"symbol": "HAVE"` - проверяет наличие статуса с положительным значением (показывает навык, если
  статус есть и его значение > 0)
- `"symbol": "EXIST"` - проверяет существование статуса независимо от значения (показывает навык,
  если статус существует, даже если значение отрицательное или равно 0)
- `"symbol": "MORE"` - проверяет, что значение больше указанного

> **⚠️ Важно: Разница между HAVE и EXIST**
>
> - **`HAVE`** проверяет наличие статуса **и** что его значение больше 0. Если статус существует, но
    имеет значение 0 или отрицательное, условие не сработает.
> - **`EXIST`** проверяет только существование статуса, независимо от его значения (даже если
    значение отрицательное или равно 0).
>
> **Когда использовать EXIST:**
> - Для статусов с отрицательными значениями (например, дебаффы типа `CHANGE_STOCK` с `value: -10`)
> - Для статусов, которые могут иметь значение 0, но должны считаться активными
>
> **Пример:**
> ```json
> {
>   "name": "В ловушке",
>   "type": "CHANGE_STOCK",
>   "value": -10,
>   "duration": -1
> }
> ```
> Для проверки наличия такого статуса используйте `"symbol": "EXIST"`, а не `"symbol": "HAVE"`.

**Комбинирование условий:**

Можно использовать несколько условий в `conditionsForDisplay` для создания сложной логики. Например,
навык может быть виден только если:

- У цели есть один статус (HAVE)
- И одновременно отсутствует другой статус (EMPTY)

```json
"conditionsForDisplay": [
{
"parameter": "STATUS",
"symbol": "HAVE",
"target": "ENEMY",
"name": "Действует"
},
{
"parameter": "STATUS",
"symbol": "EMPTY",
"target": "ENEMY",
"name": "Контратака: Кинжал"
}
]
```

Этот пример показывает навык только если у противника есть статус "Действует" И отсутствует статус "
Контратака: Кинжал".

> **⚠️ КРИТИЧЕСКИ ВАЖНО: Условия на уровне навыка vs на уровне эффекта**
>
> **Используйте `conditionsForDisplay` на уровне навыка**, если навык не должен появляться при
> определенных условиях.
> **НЕ используйте `conditions` на уровне эффекта** для контроля видимости навыка.
>
> **Проблема:** Если условие находится в `conditions` на уровне эффекта, навык все равно будет виден
> игроку, но при попытке использования покажет "Эффект не сработал", что создает плохой UX.
>
> **Правильное решение:** Перенесите условие в `conditionsForDisplay` на уровне навыка. Тогда навык
> вообще не будет показан, если условие не выполнено.
>
> **Пример неправильного использования:**
> ```json
> {
>   "name": "Серьезные последствия",
>   "effects": [
>     {
>       "command": "EDIT_STATUS",
>       "conditions": [
>         {
>           "parameter": "HP",
>           "symbol": "LESS",
>           "value": 30,
>           "target": "HERO"
>         }
>       ],
>       "probability": 10
>     }
>   ]
> }
> ```
> Проблема: Навык всегда виден, но эффект срабатывает только при HP < 30, что приводит к сообщению "
> Эффект не сработал".
>
> **Пример правильного использования:**
> ```json
> {
>   "name": "Серьезные последствия",
>   "conditionsForDisplay": [
>     {
>       "parameter": "HP",
>       "symbol": "LESS",
>       "value": 30,
>       "target": "HERO"
>     }
>   ],
>   "effects": [
>     {
>       "command": "EDIT_STATUS",
>       "probability": 10
>     }
>   ]
> }
> ```
> Правильно: Навык появляется только при HP < 30, игрок не видит его в других случаях.

### Структура условия

```json
{
  "parameter": "HP",
  "symbol": "LESS",
  "value": 50,
  "target": "HERO",
  "name": "Слабость",
  "gemType": 1
}
```

**Описание полей:**

- `parameter`: Параметр для проверки
- `symbol`: Символ сравнения
- `value`: Значение для сравнения
- `target`: Цель проверки
- `name`: Имя статуса (для STATUS)
- `gemType`: Тип ресурса (для STOCK)

## 8. Настройки игры (Settings)

### Основные настройки

```json
{
  "types": 5,
  "stopGenerate": false,
  "animateEnemy": true,
  "makeEnemyMove": true,
  "showHeroAnimation": true,
  "showHeroPortrait": true,
  "showEnemyAnimation": true,
  "gemSettings": []
}
```

**Описание полей:**

- `types`: Количество цветов гемов, которые используются в игре
  - **⚠️ Важно:** `types` не может быть меньше 4 - это минимальное количество цветов гемов, которые
    используются в игре
- `stopGenerate`: Остановить генерацию гемов (если `true`, новые гемы не будут генерироваться)
- `animateEnemy`: Анимация действий противника
  - **Если `true`**: Показываются летающие иконки навыков противника - анимация использования
    действий противником. Эффекты применяются **после завершения анимации** летающей иконки к цели
  - **Если `false`**: Действия противника выполняются мгновенно - эффекты применяются сразу, только
    информация выводится в лог
  - **⚠️ Рекомендуется:** Устанавливать `true` для лучшего визуального опыта игры
  - **Примечание:** При `animateEnemy: true` система создает `ExecutedPerk` объект, который
    запускает анимацию летающей иконки (`launchEnemySparkAnimation`). Эффекты навыка применяются в
    колбэке `onAnimationEnd` после завершения визуальной анимации. При `animateEnemy: false` все
    навыки противника выполняются последовательно через `enemyActions()` без задержек
- `makeEnemyMove`: Ход противника на игровом поле
  - **Если `true`**: От лица противника выполняется действие совместить 3 в ряд на игровом поле,
    т.е. как будто есть живой оппонент. Противник автоматически находит возможные ходы на
    поле (`findPossibleMoves()`), случайно выбирает один из них и выполняет его, кликая на
    соответствующие ячейки игрового поля
  - **Если `false`**: Противник не делает ход на игровом поле, а сразу использует навыки
    автоматически (через `startEnemyTurn()`)
  - **Примечание:** При `makeEnemyMove: true` система отправляет событие
    через `enemyMoveEventInteractor`, которое обрабатывается в `makeMove()`. Функция находит все
    возможные ходы на игровом поле, случайно выбирает один и выполняет его с небольшой задержкой,
    создавая эффект живого оппонента. После завершения хода на поле вызывается `makeEnemyTurn()`,
    который запускает `startEnemyTurn()` для применения навыков противника
- `showHeroAnimation`: Показывать анимацию героя (включает/выключает анимацию героя)
- `showHeroPortrait`: Показывать портрет героя (включает/выключает отображение портрета героя)
  - **⚠️ Важно:** Если герой - Рук, то нужно установить `showHeroAnimation: true`
    и `showHeroPortrait: true`
- `showEnemyAnimation`: Показывать анимацию противника (включает/выключает анимацию противника)
- `gemSettings`: Настройки гемов (массив объектов `GemSettings`, см. ниже)

#### Структура настроек гема

```json
{
  "type": "1",
  "name": "axe_shield",
  "fullValue": 10,
  "halfProbability": 25,
  "bonusValue": 2,
  "bonusProbability": 20,
  "extraProbability": 25,
  "turnKeepStrategy": 50,
  "damageKeepStrategy": 100,
  "displayName": "оружия"
}
```

**Описание полей:**

- `type`: Тип гема (строка, например "1", "2", "3" и т.д.) - определяет цвет гема
- `name`: Название гема (используется для идентификации, например "axe_shield", "armor", "move")
  - **⚠️ Важно:** Иконка гема определяется автоматически на основе поля `name`, поэтому поле `uri`
    не нужно задавать
- `fullValue`: Полное значение гема - базовое количество очков, которое дает гем при совпадении (по
  умолчанию 10)
- `halfProbability`: Вероятность половинного значения (в процентах 0-100) - вероятность того, что
  гем будет иметь дебаф и давать уменьшенное значение (`fullValue / 2`) вместо `fullValue`. При
  срабатывании этой вероятности гем получает `extraType = EMPTY_COLOR`
- `bonusValue`: Бонусное значение - дополнительное количество очков, которое дает гем, если на нем
  есть бонус (по умолчанию 2). Бонусный гем имеет `bonusType` с другим цветом гема
- `bonusProbability`: Вероятность бонуса (в процентах 0-100) - вероятность того, что на геме будет
  бонус (`bonusType`), дающий дополнительные очки при совпадении
- `extraProbability`: Вероятность дополнительного цвета (в процентах 0-100) - вероятность того, что
  гем будет иметь дополнительный цвет (`extraType`). Гем с дополнительным цветом может совпадать с
  гемами как основного, так и дополнительного цвета, давая очки за оба типа
- `turnKeepStrategy`: Процент сохранения очков после хода (в процентах 0-100) - определяет, какой
  процент накопленных очков сохранится после завершения хода
- `damageKeepStrategy`: Процент сохранения очков после получения урона (в процентах 0-100) -
  определяет, какой процент накопленных очков сохранится после получения урона героем (работает
  только при атаках, отрицательное лечение не оказывает эффекта)
- `displayName`: Отображаемое имя - название типа гема, которое будет показано игроку (например, "
  оружия", "корпуса", "движения")

## 9. Правила героя (HeroRules)

Правила героя определяют, какие эффекты применяются при совпадении гемов на игровом поле. Правила
срабатывают автоматически при совпадении гемов, соответствующих условиям правила.

### Структура правил

`HeroRules` - это массив объектов `MatchRule`, каждый из которых описывает условие совпадения и
перк, который нужно применить.

```json
{
  "HeroRules": [
    {
      "name": "4_gems_color_1",
      "orientation": null,
      "gemType": 1,
      "minSize": 4,
      "perk": {
        "name": "Гемокомбо: Тип 1",
        "description": "Совпадение 4 камней цвета 1",
        "effects": [
          {
            "command": "EDIT_STATUS",
            "type": "CHANGE",
            "value": 1,
            "status": {
              "name": "Гемокомбо: Тип 1",
              "type": "GENERATE",
              "gemTypes": [1],
              "value": 1,
              "duration": 1
            },
            "target": "HERO"
          }
        ]
      }
    }
  ]
}
```

### Поля правила (MatchRule)

- `name`: Уникальное имя правила (строка)
- `orientation`: Ориентация совпадения или `null` для любой ориентации
  - `"VERTICAL"`: Вертикальное совпадение (столбец)
  - `"HORIZONTAL"`: Горизонтальное совпадение (ряд)
  - `"T_SHAPE"`: Т-образное совпадение
  - `"L_SHAPE"`: L-образное совпадение
  - `"OTHER"`: Другая форма
  - `null`: Любая ориентация
- `gemType`: Тип камня (число от 0 до 5) или `null` для любого типа
- `minSize`: Минимальный размер совпадения (по умолчанию 3)
- `perk`: Объект перка, который применяется при выполнении условия (см. раздел 4)

### Использование поля `times` в статусах

Поле `times` в статусе определяет, сколько раз статус может быть использован. Если поле не указано,
статус действует столько раз, сколько длится его `duration`.

**Примеры:**

```json
{
  "name": "Гемосила",
  "type": "STRONG",
  "value": 1,
  "duration": 1,
  "times": 1
}
```

Статус действует 1 ход, но может быть использован только 1 раз. После использования статус исчезает,
даже если ход еще не закончился.

```json
{
  "name": "Мощный бафф",
  "type": "STRONG",
  "value": 2,
  "duration": 3,
  "times": 2
}
```

Статус длится 3 хода, но может быть использован только 2 раза. Если статус использован 2 раза до
окончания 3 ходов, он исчезает.

### Важные моменты

1. **Приоритет правил:** Если совпадение соответствует нескольким правилам, все они срабатывают
2. **Ориентация:** Если `orientation` указана, правило срабатывает только для совпадений этой
   ориентации
3. **Тип камня:** Если `gemType` указан, правило срабатывает только для камней этого типа
4. **Минимальный размер:** Правило срабатывает для совпадений размера `minSize` и больше
5. **Цель эффекта:** Обычно эффекты правил применяются к герою (`target: "HERO"`), но можно указать
   и другую цель

## 10. Продвинутые примеры

### Пример 1: Сложная функция вероятности с несколькими сегментами

Следующий пример показывает, как создать эффект, вероятность которого зависит от нескольких
параметров:

```json
{
  "command": "EDIT_STATUS",
  "target": "HERO",
  "value": 1,
  "type": "SET",
  "probability": -15,
  "pFunc": {
    "segments": [
      {
        "parameter": "STOCK",
        "gemType": 5,
        "source": "HERO",
        "mul": 1
      },
      {
        "parameter": "STATUS",
        "name": "Слух",
        "source": "HERO",
        "mul": 5
      },
      {
        "parameter": "STATUS",
        "name": "Обыск",
        "source": "HERO",
        "mul": 4
      }
    ]
  },
  "status": {
    "name": "Ладрон: Найден",
    "description": "Гуль Ладрон найден",
    "type": "INFO",
    "value": 1,
    "duration": -1
  }
}
```

**Расчет вероятности:**

- Игрок имеет 50 очков голоса (gemType 5)
- У игрока статус "Слух" со значением 2
- У игрока статус "Обыск" со значением 3
- **Итоговая вероятность** = (50 × 1) + (2 × 5) + (3 × 4) - 15 = 50 + 10 + 12 - 15 = 57%

**Полезные паттерны:**

- Используйте высокие множители для редко получаемых статусов (например, `mul: 5` для "Слух")
- Комбинируйте ресурсы (STOCK) со статусами для сложной системы вероятностей
- Используйте отрицательную базовую вероятность, чтобы требовать от игрока активных действий

## 12. Взаимное обнуление статусов

### Когда использовать

При создании навыков, которые меняют форму или состояние персонажа, часто требуется обнулить
противоположное состояние. Например, если персонаж принимает "большую форму", нужно сбросить "малую
форму", и наоборот.

### Правильная реализация

**Пример: Навыки изменения формы тела**

```json
{
  "name": "Увеличить тело",
  "conditionsForDisplay": [
    {
      "parameter": "STATUS",
      "name": "Большой",
      "symbol": "EMPTY",
      "target": "HERO"
    }
  ],
  "effects": [
    {
      "command": "EDIT_STATUS",
      "type": "SET",
      "target": "HERO",
      "value": 0,
      "status": {
        "name": "Маленький",
        "type": "INFO",
        "value": 0,
        "duration": -1
      }
    },
    {
      "command": "EDIT_STATUS",
      "type": "SET",
      "target": "HERO",
      "value": 2,
      "status": {
        "name": "Большой",
        "type": "CHANGE_STOCK",
        "value": 2,
        "duration": -1
      }
    }
  ]
}
```

**Ключевые моменты:**

1. **Условие видимости:** Навык не должен быть доступен, если соответствующая форма уже
   активна (`conditionsForDisplay` с `EMPTY`)
2. **Порядок эффектов:** Сначала обнулите противоположный статус, затем установите новый
3. **Тип обнуления:** Используйте `EDIT_STATUS` с `type: "SET"` и `value: 0` для обнуления статуса

**Пример для противоположного навыка:**

```json
{
  "name": "Уменьшить тело",
  "conditionsForDisplay": [
    {
      "parameter": "STATUS",
      "name": "Маленький",
      "symbol": "EMPTY",
      "target": "HERO"
    }
  ],
  "effects": [
    {
      "command": "EDIT_STATUS",
      "type": "SET",
      "target": "HERO",
      "value": 0,
      "status": {
        "name": "Большой",
        "type": "CHANGE_STOCK",
        "value": 0,
        "duration": -1
      }
    },
    {
      "command": "EDIT_STATUS",
      "type": "SET",
      "target": "HERO",
      "value": 1,
      "status": {
        "name": "Маленький",
        "type": "INFO",
        "value": 1,
        "duration": -1
      }
    }
  ]
}
```

> **💡 Важно:** При обнулении статуса типа `CHANGE_STOCK` обязательно указывайте `gemTypes` в
> структуре статуса, даже если значение равно 0.

### Для социальных сцен

- Используйте HP как "доверие" или "интерес"
- Создавайте навыки для манипуляции ресурсами репутации
- Добавляйте случайные события через enemy perks
- Используйте статусы для долгосрочных эффектов

### Для боевых сцен

- Создавайте разнообразные типы атак (физические, магические)
- Используйте статусы для тактических эффектов
- Добавляйте условия для активации специальных навыков
- Создавайте противников с уникальными механиками

### Общие принципы

- Тестируйте баланс сложности
- Используйте описания для погружения в мир
- Создавайте интересные комбинации эффектов
- Учитывайте прогрессию сложности
- **Всегда используйте `conditionsForDisplay` для контроля видимости навыков, а не `conditions` в
  эффектах**
- **При создании взаимоисключающих состояний (формы, режимы) обнуляйте противоположные статусы**
- Документируйте сцену (технический md, при необходимости player-md); после тестовых прохождений
  ведите краткий результат и художественную интерпретацию по логу — см. раздел 16 и *
  *RESULT_INTERPRETATION_GUIDE.md**

## 14. Отладка и тестирование

### Проверочный список

- [ ] Все обязательные поля заполнены
- [ ] Ссылки на gemType корректны
- [ ] Условия логически правильны
- [ ] Вероятности в диапазоне 0-100
- [ ] Длительности статусов разумны
- [ ] Стоимости навыков сбалансированы

### Частые ошибки

- Неправильные типы данных (строка вместо числа)
- Отсутствующие обязательные поля
- Некорректные ссылки на gemType
- Циклические зависимости в условиях
- Слишком высокие или низкие значения
- **Отсутствие поля `value` на уровне эффекта для `EDIT_STATUS`** - это критическая ошибка, которая
  может привести к неправильной работе эффекта
- **Неполная структура статуса при восстановлении** - при восстановлении статуса нужно указывать все
  его поля (duration, probability, reactionEffect и т.д.)
- **Использование `conditions` в эффектах для контроля видимости навыка** - это приводит к тому, что
  навык всегда виден, но показывает "Эффект не сработал". Используйте `conditionsForDisplay` на
  уровне навыка вместо этого
- **Отсутствие условий видимости для взаимоисключающих навыков** - если навык не должен быть
  доступен
  при определенном статусе (например, "увеличить тело" не должно быть видно, если уже есть статус
  "Большой"), добавьте `conditionsForDisplay` с проверкой `EMPTY`
- **Отсутствие обнуления противоположных статусов** - при смене формы/режима всегда обнуляйте
  противоположный статус первым эффектом в массиве `effects`

### Рекомендации

- Сохраняйте резервные копии файлов
- Тестируйте изменения в игре после каждого обновления
- Используйте осмысленные имена для полей
- Группируйте связанные настройки вместе

## 16. Документирование сцены и интерпретация результатов

### Документирование при создании сцены

- **Техническое описание** (например, `rebeld_8_neg.md`) — полная механика: HP/репутация/интерес,
  секторы, навыки с условиями, вероятности, статусы. Нужно для реализации в JSON и для правок
  баланса.
- **Описание для игрока** (например, `*_player.md`) — без спойлеров: общая цель, примерные эффекты
  навыков (~+1 репутации, «есть шанс поднять или потерять интерес»), цены, ограничения по
  зарядам/перезарядке. Описания в JSON (`description` у перков) лучше держать в том же стиле —
  ориентировочно, без раскрытия секторов и точных формул.

### После прохождения: результат и художественная интерпретация

По логу прохождения сцены (battle log) удобно вести два файла:

- **`*_results.md`** — краткая сводка для дизайна: контекст сцены, как менялась репутация/HP по
  ходам (общая канва), итоговый результат. Отдельно упоминать стоит только: часто используемые
  навыки (как приобретённый опыт), навыки с лимитом (charges) и навыки/статусы, влияющие на события
  за пределами сцены.
- **`*_story.md`** — художественное повествование для игрока/сюжета: предыстория сцены (связь с
  предыдущими испытаниями), интерпретация событий по логу, при необходимости — реплики и рефлексия
  героя, без перечисления механики и цифр.

Подробные правила оформления результатов и story, а также как читать лог и что выносить в «важные
навыки», описаны в **RESULT_INTERPRETATION_GUIDE.md**.

Это руководство поможет создавать интересные и сбалансированные сцены для игры "Twilights".
Экспериментируйте с различными комбинациями эффектов и механик, чтобы создавать уникальный игровой
опыт.
