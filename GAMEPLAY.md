# Игровой цикл Twilights (GAMEPLAY)

Twilights — **не классический match-3**. Это RPG-инструмент для настольной игры: один **ход** =
одно **успешное совмещение** на доске (плюс каскады от него) → трата очков на **навыки** → конец
хода. Игрок **не** может свайпать доску сколько угодно раз за ход.

Этот документ — контракт механики для AI, порта в веб и баланса сцен. Архитектура кода —
`PROJECT_CONTEXT.md`; JSON сцен — `SCENE_CREATION_GUIDE.md`.

---

## Термины

| Термин | Значение |
|--------|----------|
| **Ход (turn)** | Полный цикл одной стороны: совмещение → (опционально) навыки → передача хода |
| **Свайп (swap)** | Обмен двух соседних гемов на доске |
| **Успешный свайп** | Свайп, после которого на поле есть совпадение 3+ |
| **Совпадение (match)** | Связная группа из 3+ гемов одного типа в ряд или столбец |
| **Каскад (cascade)** | Цепочка: после удаления совпадений гемы падают, появляются новые (`stopGenerate: false`) → новые совпадения. Всё это **один ход**, не отдельные свайпы |
| **Сток (stock)** | Ресурс определённого `gemType`; копится с доски и тратится на перки |
| **Перк (perk)** | Навык из руки (Hand); стоит очки, применяет эффекты |

**Не путать:** «один перк из категории за ход» (`category` + `coolDown` + `reloadType: TURN`) —
это ограничение **навыков**, а не доски. За ход всё равно **одно** успешное совмещение.

## Ход героя

```
┌─────────────────────────────────────────────────────────────┐
│ 1. Доска открыта, таймер хода идёт                          │
│ 2. Игрок делает свайп                                       │
│    • нет совпадения → гемы возвращаются, можно пробовать    │
│      снова (лимита попыток нет)                             │
│    • есть совпадение → доска ЗАКРЫВАЕТСЯ (coverBoard),      │
│      таймер останавливается — второй свайп в этом ходу      │
│      невозможен                                              │
│ 3. Каскады: удаление → падение → генерация → новые матчи    │
│ 4. Каскады закончились → начисление стоков, HeroRules,      │
│      в лог: «За ход: …» и «Время хода: …»                   │
│ 5. Игрок тратит очки на перки (0..N, см. ниже)              │
│ 6. «Закончить ход» → EndTurnExecutor → ход противника       │
└─────────────────────────────────────────────────────────────┘
```

### Один успешный свайп за ход

После **первого** успешного совпадения в ходе героя:

- вызывается `GameBoardAdapter.Callback.onHandleMatches()`;
- `GameScreen` ставит `coverBoard` поверх доски (`updateCoverBoard(VISIBLE)`);
- таймер хода останавливается.

Доска снова открывается только в **начале следующего** хода героя
(`startTurnAgainEvent` → `coverBoard GONE`).

Неудачные свайпы (без линии 3+) откатываются (`swapWithMistake`) — доска остаётся открытой.

### Каскады

`GameBoardAdapter.handleMatches()` крутит цикл, пока:

- при `stopGenerate: false` — есть совпадения **или** пустые ячейки;
- при `stopGenerate: true` — есть совпадения (новые гемы не генерируются).

Все группы за этот цикл дают очки и срабатывают правила — это **один** ход героя на доске.

### Навыки за ход героя

После каскадов (`allowEndTurn`) игрок **может использовать несколько перков**, если хватает
ресурсов и нет других ограничений.

**Ограничение «один из категории»:** перки с одинаковым `category`, `coolDown: 1` и
`reloadType: "TURN"` взаимоисключающи — после одного из них остальные категории недоступны до
следующего хода. См. `SCENE_CREATION_GUIDE.md`.

Перк доступен, когда `perk.show && perk.enable` (ресурсы, перезарядка, `conditionsForEnable`).

### Лог боя (ход героя)

| Строка | Когда | Смысл |
|--------|-------|-------|
| `Действует {герой}` | Начало хода | Герой может ходить на доске |
| `Время хода:{сек}` | После первого успешного свайпа | Секунды от старта таймера до совмещения |
| `За ход: тип: +N, …` | После каскадов | Прирост стоков за весь свайп+каскад (текущие − снимок на начало хода) |
| Сообщения перков | По клику | Эффекты навыков |

Снимок стоков на начало хода: `HeroStockListInteractor.saveTurnStartSnapshot()` — после
`updatePersonStocksAfterTurn()` в конце хода противника.

## Ход противника

```
┌─────────────────────────────────────────────────────────────┐
│ 1. «Действует {противник}»                                  │
│ 2. Статусы врага (урон, генерация и т.д.), щиты сбрасываются│
│ 3. Если makeEnemyMove: true                                 │
│    • один случайный свайп из findPossibleMoves()            │
│    • каскады от этого свайпа (очки врага, его правила)      │
│ 4. Все доступные перки врага подряд (см. ENEMY_AI.md)       │
│ 5. Конец хода врага → giveTurnToHero() → ход героя          │
└─────────────────────────────────────────────────────────────┘
```

### AI противника на доске

При `makeEnemyMove: true` (`GameScreen.makeMove()`):

1. Случайный ход из всех легальных свайпов.
2. **Один** свайп за ход врага (как у героя).
3. После каскадов — `makeEnemyTurn()` → применение навыков.

При `makeEnemyMove: false` враг **не** трогает доску, сразу `enemyActions()`.

### AI противника — навыки

`EndTurnExecutor.enemyActions()` перебирает `EnemyHands` сверху вниз; для каждой видимой руки —
все перки, где `perk.show && perk.enable`. **Используются все подходящие**, не один «лучший».

Подробнее: `ENEMY_AI.md`.

## Правила совпадений (HeroRules / EnemyRules)

- **HeroRules** срабатывают только при `heroTurn == true` (`MatchPerkExecutor`).
- Правила врага на доске — при ходе врага (`heroTurn == false`).
- Движок разбивает поле на **связные группы** одного цвета; для каждой группы проверяются все
  подходящие правила (несколько может сработать за один ход доски).
- Ориентация (горизонталь / вертикаль) важна, если задана в правиле. Г- и Т-образные группы
  получают только правила без требования ориентации (см. примеры в `*_player.md`).

Базовые очки за гемы: `UpdateStockExecutor` + `gemSettings` (`fullValue`, `halfProbability`,
множители клеток `Settings.cells`).

## Автоматические системы (вне свайпа)

| Система | Когда срабатывает |
|---------|-------------------|
| **Статусы** (`DAMAGE`, `HEAL`, `GENERATE`…) | Начало/конец хода (`applyPersonStatus`, `end: true/false`) |
| **TimePerks** | Каждую секунду таймера сцены |
| **StockPerks** | При изменении стока (пересечение порога снизу вверх) |
| **HeroStates / EnemyStates** | Автостатусы по условиям (`PerkExecutor.updatePersonsStates`) |
| **Триггер-клетки** (`cellType: TRIGGER`) | При совпадении через клетку |

Они **не** заменяют свайп и **не** дают второй свайп за ход.

## Settings, влияющие на цикл

| Поле | Эффект на ход |
|------|----------------|
| `stopGenerate` | `true` — без догенерации; каскады короче, но всё равно 1 свайп |
| `makeEnemyMove` | Враг делает 1 свайп перед навыками |
| `types` | Число цветов на доске (минимум **4**) |
| `gemSettings[].turnKeepStrategy` | % стока, сохраняемый между ходами (после хода врага) |
| `gemSettings[].damageKeepStrategy` | % стока после получения урона героем |
| `animateEnemy` | Анимация перков врага vs мгновенное применение |

## Соответствие кода (Android)

| Правило | Где в коде |
|---------|------------|
| 1 успешный свайп героя | `GameBoardAdapter.changeItems` → `onHandleMatches`; `GameScreen.updateCoverBoard` |
| Блокировка доски | `coverBoard` в `GameScreen` |
| Каскады | `GameBoardAdapter.handleMatches` |
| Очки с доски | `UpdateStockExecutor.addValueFromCrushedGems` |
| HeroRules | `MatchPerkExecutor.execute` |
| «За ход» в логе | `GameScreenViewModel.logPoints` |
| Конец хода героя | `GameScreenViewModel.endTurn` → `EndTurnExecutor.execute` |
| 1 свайп врага | `GameScreen.makeMove` |
| Все перки врага | `EndTurnExecutor.enemyActions` |
| Начало хода героя | `EndTurnExecutor.giveTurnToHero` |

## Чеклист для порта (веб и др.)

При реализации клиента **обязательно** воспроизвести:

- [ ] **Не** бесконечные свайпы за ход — ровно **одно успешное совмещение**, затем фаза навыков.
- [ ] Неудачный свайп откатывается; успешный закрывает доску до следующего хода героя.
- [ ] Каскады после одного свайпа — один расчёт очков и HeroRules на весь каскад.
- [ ] `За ход` = дельта стоков от снимка на начало хода, не «за один матч в каскаде».
- [ ] После каскадов игрок может применить **несколько** перков (если хватает ресурсов).
- [ ] Враг: опционально 1 свайп, затем **все** `enable` перки по порядку рук.
- [ ] `HeroRules` только в ход героя; правила врага — в ход врага.
- [ ] `stopGenerate` влияет на каскады, **не** на лимит «1 свайп».

Типичная ошибка порта: скопировать `GameBoard` / `handleMatches`, но оставить доску активной
после совмещения — получится обычный match-3, ломающий баланс сцен.
