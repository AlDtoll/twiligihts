# Characterization tests

Эти тесты фиксируют **текущее** поведение игровой логики (`logic/`, `model/`) перед переводом UI с XML на Compose. Логика не менялась. Если поведение похоже на баг, тест всё равно фиксирует его как есть и помечен `// SUSPECT-N`. Список и описание — в `SUSPECTS.md` пилота modernize.

- `RULE-NNN` в комментариях ссылается на карточку правила в `BUSINESS_RULES.md`.
- `Fixture.kt` собирает граф объектов вручную (вместо Hilt), как в `@Inject`-конструкторах.
- Вероятности в тестах только 100% (или −1 для гарантированного провала), поэтому `Random` в коде не влияет на результат.

## Запуск

Обычный способ: `./gradlew :app:testDebugUnitTest --tests 'aldtoll.twiligihts.characterization.*'` (JUnit4 уже подключён в `app/build.gradle`).

Без Gradle (так тесты гонялись на VPS): скрипт `run-tests.sh` компилирует нужные исходники через `kotlinc` 1.7.20 с JVM-заглушками для `androidx.lifecycle`, `androidx.annotation`, `android.util.Log`, Firebase-аннотаций и `R`. Отличие стенда от устройства: `MutableLiveData.postValue` применяется синхронно.

## Как добавить кейс

1. Найти правило в `BUSINESS_RULES.md` или добавить новую карточку.
2. Собрать состояние через `Fixture` (`f.hero`, `f.heroStocks(...)`, `f.heroHand(...)`).
3. Вызвать исполнитель и проверить конкретные числа. Ожидаемое значение берётся из того, что код делает сейчас, а не из того, что «должно быть».
